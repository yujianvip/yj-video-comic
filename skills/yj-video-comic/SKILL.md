# 360°视频互动漫画

把每段完整环绕一周的视频视为一个漫画格。用户横向拖动时，将角度映射到对应视频帧，而不是按时间连续播放。

## 工作流

1. 明确输入视频目录、主题、标题、语言和输出目录。视频按文件名自然排序；推荐 `01.mp4`、`02.mp4`。
2. 用 `ffprobe` 检查每段视频。发现无法解码、时长为零、画面方向错误或并非完整一周时，停止并说明具体文件。
3. 如用户只给主题，先从各视频抽取 0°、90°、180°、270° 四张观察帧，再依据画面拟定每格旁白。不要仅凭文件名编造剧情。
4. 如需精确输入格式或清单字段，读取 [references/input-schema.md](references/input-schema.md)。整页格线必须由相邻画格共用，缝隙保持很窄；文字框始终靠某条边。用户指定 `style.frameShape`、`panels[].shape` 或 `panels[].captionPosition` 时遵从其设置及吸附规则。
5. 生成 `manifest.json`，然后运行：

   ```powershell
   node scripts\build-comic.mjs --manifest "<清单路径>" --out "<输出目录>"
   ```

6. 生成器默认把视频转为全关键帧 H.264 MP4，以保证拖动时可以可靠随机定位。只有用户明确要求保留原文件，或已验证文件为全关键帧编码时，才使用 `--copy-video`。
7. 运行生成目录中的本地预览服务器，不要直接依赖 `file://`：

   ```powershell
   node scripts\serve.mjs --root "<输出目录>" --port 4173
   ```

8. 在桌面和窄屏各检查一次：页面载入、拖动旋转、点击聚焦、上一格/下一格、自动旋转、复位、网点开关、键盘操作、视频首尾衔接，以及不规则裁切和文字是否位于所属画格内。

## 输出要求

- 输出必须是可部署到任意静态托管的相对路径网站。
- 保留 `manifest.json`，使用户能修改文案后重复生成。
- 不覆盖非空输出目录；除非用户明确要求，先使用新目录。
- `index.html` 不包含用户机器的绝对路径。
- 主题用于故事与视觉方向，标题和每格旁白仍必须与视频画面相符。
- 彩蛋、对白尾巴位置等视觉语义没有可靠依据时不自动伪造；留在清单中供后续增补。

## 依赖和失败处理

- 需要 Node.js 18+、`ffmpeg` 和 `ffprobe`。
- 缺少依赖时报告实际缺项，不悄悄降级。
- FFmpeg 转码失败时保留已生成的日志和清单，不生成“看似成功”的空网站。
- 网站运行时从 jsDelivr 加载 Three.js；离线交付时应另行下载并改用本地模块，不能声称 CDN 版本完全离线。
